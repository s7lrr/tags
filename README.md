# TAG MANAGER — Discord Bot + Web Dashboard

بوت مستقل بدون قاعدة بيانات خارجية. الإعدادات والأونرات والسجلات تحفظ في ملفات JSON محلية.

## المكونات
- Discord bot باستخدام discord.py.
- Web Dashboard باستخدام aiohttp، يعمل ضمن نفس عملية البوت.
- Discord Dashboard عبر `$panel` مع أزرار وقوائم تفاعلية.
- التخزين المحلي في `data/owners.json`, `data/servers.json`, `data/logs.json`.
- لا يوجد Supabase أو PostgreSQL أو خدمة قاعدة بيانات خارجية.

## التشغيل على Windows 10/11
1. ثبّت Python 3.10 أو أحدث.
2. فك ضغط المشروع وافتح PowerShell داخل المجلد.
3. أنشئ بيئة وثبّت المتطلبات:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

4. انسخ `.env.example` إلى `.env`.
5. أدخل:
   - `DISCORD_TOKEN`: توكن البوت من Discord Developer Portal.
   - `MAIN_OWNER_ID`: رقم حساب Discord الخاص بمالك البوت.
   - `WEB_PASSWORD`: كلمة مرور قوية للوحة الويب.
   - `WEB_SECRET`: قيمة عشوائية طويلة وسرية.
6. فعّل Message Content Intent وServer Members Intent من Developer Portal.
7. شغّل:

```powershell
python bot.py
```

8. افتح لوحة الويب محلياً:
   `http://127.0.0.1:8080`

## أوامر Discord
- `$help` قائمة الأوامر.
- `$panel` أو `$dashboard` لوحة تحكم تفاعلية داخل Discord.
- `$settag S7` تحديد التاق.
- `$setrole @Role` تحديد الرتبة.
- `$setlog #channel` تحديد روم اللوق.
- `$config` عرض إعدادات السيرفر.
- `$sync` يوضح حالة المزامنة وحدود البيانات المتاحة؛ لا يستطيع جلب Server Tag لكل عضو عبر REST بشكل مضمون.
- `$owners` عرض الأونرات (مالك البوت الأساسي فقط).
- `$owner add @user` إضافة أونر (مالك البوت الأساسي فقط).
- `$owner remove @user` إزالة أونر (مالك البوت الأساسي فقط).

الأونرات الإضافيون يمكنهم استخدام إعدادات السيرفر واللوحة، لكن لا يمكنهم إدارة قائمة الأونرات.

## لوحة الويب
- Dashboard: حالة البوت والإحصائيات والسيرفرات.
- إعدادات التاق: اختيار السيرفر والتاق والرتبة وروم اللوق.
- سجل الأحداث: آخر 200 حدث.
- أونرات البوت: الإضافة والإزالة للمالك الأساسي فقط.

## أمان مهم
- لوحة الويب مربوطة افتراضياً على `127.0.0.1` ولا تكون متاحة من الإنترنت.
- لا تغيّر `WEB_HOST` إلى `0.0.0.0` إلا إذا وضعت Reverse Proxy مع HTTPS وحماية مناسبة.
- كلمة مرور لوحة الويب ليست بديلاً عن HTTPS عند نشرها للعامة.
- لا ترفع `.env` إلى GitHub ولا ترسل توكن البوت لأحد.
- ملفات JSON محلية؛ خذ نسخة احتياطية من مجلد `data` قبل نقل المشروع.

## قيد Discord Server Tag
ميزة المراقبة تعتمد على وصول `primary_guild` في بيانات Gateway ضمن `GUILD_MEMBER_UPDATE`. عُدّل المستمع ليتعامل مع `primary_guild: null` كإزالة للتاق، ويتجاهل التحديثات التي لا تحتوي المفتاح حتى لا يسحب الرتبة بالخطأ. مع ذلك، Discord لا يضمن إرسال كل تغييرات Server Tag إلى تطبيقات البوت، ولا يتيح endpoint رسميًا مضمونًا لجلب Server Tag لكل أعضاء السيرفر؛ لذلك لا يمكن ضمان اكتشاف كل زيادة أو نقصان أو إجراء مزامنة شاملة. يجب أن يكون البوت موجودًا في السيرفر، وأن تضبط التاق والرتبة وروم اللوق مرة واحدة. فعّل Server Members Intent، وامنح البوت Manage Roles، وارفع رتبة البوت فوق الرتبة المستهدفة. لا يستخدم المشروع Self-bot أو توكن حساب شخصي.


## الفحص الدوري كل 30 ثانية

بعد تشغيل البوت وضبط التاق والرتبة، يبدأ `periodic_tag_scan` بفحص أعضاء كل سيرفر مضبوط كل 30 ثانية باستخدام واجهة Discord الرسمية `GET /guilds/{guild_id}/members` مع التصفح على دفعات تصل إلى 1000 عضو. تتم قراءة `user.primary_guild` عندما يكون موجوداً في بيانات العضو.

- إذا كان التاق مطابقاً للسيرفر والتاق المحدد، يضيف البوت الرتبة عند الحاجة.
- إذا كانت `primary_guild` موجودة وصريحة وتدل على عدم عرض التاق المطلوب، يسحب البوت الرتبة عند الحاجة.
- إذا لم يرجع Discord حقل `primary_guild`، يعتبر العضو غير قابل للتحقق في هذه الدورة ولا يسحب رتبته تخميناً.
- الأمر `$sync` يشغّل فحصاً فورياً ويعرض عدد الأعضاء المفحوصين والتغييرات والبيانات غير المتاحة.

تنبيه: الفحص كل 30 ثانية هو تكرار مجدول، لكن مدة فحص السيرفر الكبير قد تتجاوز 30 ثانية بسبب عدد الصفحات وحدود Discord. مكتبة discord.py تتعامل مع حدود الطلبات. كما أن اكتمال الفحص يعتمد على أن Discord يعيد `primary_guild` ضمن User Object للأعضاء؛ راقب عداد «بيانات غير متاحة» في نتيجة `$sync` وسجل `bot.log`. لا تستخدم توكن حساب شخصي؛ يلزم Bot Token رسمي فقط.
